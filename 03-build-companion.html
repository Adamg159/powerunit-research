Part 1How the system works, end to end

The ground rule that shapes everything. The ignition world and the electronics world never share power or wiring. The CDI generates 15–20 kV pulses inches from the logic boards; the only reliable defense is isolation. The electronics have their own 2S battery feeding an MP1584 buck at 5.0 V; that rail powers the ESP32 (whose onboard regulator makes 3.3 V), the SD module, and the Hall sensor. Any signal that must cross between worlds does so as a sealed digital pulse or through an optocoupler, where it crosses as light with no shared wire. Ferrites, shielded cable, TVS clamps, and star grounding all reinforce this one wall.

The combustion side. The flywheel carries the CDI’s magnet; each revolution it sweeps the CDI’s Hall sensor, which tells the CDI box “piston near top,” and the CDI fires the plugs. Stock timing is fixed — the spark fires at the same crank angle at every RPM. All of Phase 1 runs this way.

Sensing — three one-way conversations into the ESP32. Head temperature: a K-type washer thermocouple generates microvolts at its junction; the MAX31855 sits nearby, amplifies, cold-junction compensates, and answers the ESP32 over SPI — one per cylinder so the two carbs can be caught disagreeing. RPM: a separate SmCo magnet sweeps a separate A3144 Hall sensor (never the ignition’s), one pulse per rev into the ESP32’s hardware pulse counter, which counts edges with no software in the loop. Vibration: the MPU-6050 reports over I2C, building the “healthy baseline” that later changes are measured against.

The hub. The telemetry ESP32 is the scribe: it timestamps every reading so temperature, RPM, and vibration become one synchronized story, then sends it out three ways — microSD (SPI) as ground truth, WiFi to the laptop dashboard for live monitoring with zero wires to the bench, and USB serial for engine-off debugging.

Phase 2 — the electric side. The brushless motor belt-couples to the crank; torque flows both directions. The VESC converts battery DC to three-phase motor current and works in all four quadrants: it can spin the engine (start, assist) or resist it (dyno load, harvest). VESC and telemetry ESP32 talk UART — the system’s only true dialogue: commands go one way, and motor RPM, phase current, and battery volts/amps come back, which is the entire electrical half of the energy dataset for free. The ESP32 graduates from scribe to energy manager.

Phase 2 — the second brain. Fixed spark timing is wrong at most RPMs; the flame needs a head start that grows with engine speed. A dedicated ignition ESP32 intercepts the crank pulse (through an opto), looks up the correct advance in an RPM-indexed map with hard-coded limits, waits precisely the right microseconds, and fires the CDI trigger (through another opto). It is a separate chip because WiFi and file writes cause millisecond pauses — nothing in a log entry, tens of degrees of error in spark timing. The interface is a plug swap: pull one connector and stock fixed timing is back. The telemetry ESP32 logs commanded advance beside RPM and head temp, so every map becomes data.

Phase 3 adds pitot pressure and ride-height sensors as more digital breakouts on the same buses, flowing down the same SD/WiFi paths, compared against CFD. Nothing structural changes — that is the payoff of the architecture.

Part 2Arrival-day checklists

Electronics (this week — do while return windows are open)

  • Flash a blink + WiFi-scan sketch on all three ESP32s. If one won’t enumerate over USB, swap the cable before blaming the board.
  • Power each MP1584 buck alone and set its trim pot to 5.0 V with a multimeter before it ever touches a board. They arrive at random setpoints.
  • Run h2testw on the Lexar card — full write/verify pass to confirm genuine capacity before it holds engine data.
  • Solder headers onto the MPU-6050 boards (lab iron is fine if the TS101 hasn’t arrived). No friction-fit on a vibration sensor.
  • Breadboard the Hall sensor: 5 V supply, 10 k pull-up to 3.3 V on the output. Test each SmCo magnet’s polarity — the A3144 is unipolar — and paint-mark the working face of every magnet you plan to use.
  • Wire a MAX31855 and confirm it reads room temperature sanely (any K-type probe or even shorted input for a fault-bit check).
  • SD module: VCC from the 5 V rail, never 3.3 V. If writes are flaky on jumper wires, drop the SPI clock speed first.
  • TS101: run the IronOS firmware updater once — it recognizing the iron confirms a genuine unit while the return window is open.

Engine (weeks out — full checklist in document 2, section 2)

  • Photograph everything before assembly; verify bundle contents; identify the starter-harness connector (unlocks the battery buy); inventory exhaust parts; inspect machining and dry-fit.
  • Measure head-bolt / plug-seat hardware with calipers — this sizes the washer thermocouple order (prefer ungrounded/insulated-junction probes).

EMI rules, compressed: electronics on their own battery, never the ignition supply · all grounds meet at one star point · cable shield drain lands at the star point only, one end · ferrites clamp at the receiving end of each run, thin cables looped through twice · P6KE6.8CA TVS on 5 V lines, P6KE12CA on 2S battery leads · 0.1 µF ceramic at every board’s power pins, bulk electrolytic at buck outputs · physical distance between ignition wiring and signal wiring beats every other fix.

Part 4Pre-arrival study guide

This week, matched to the electronics arriving

  • Random Nerd Tutorials (site) — tested ESP32 guides for nearly every module ordered. Search: ESP32 MAX31855, ESP32 microSD logging, ESP32 MPU-6050, ESP32 web server dashboard.
  • DroneBot Workshop (YouTube) — clearest long-form ESP32 introductions. Andreas Spiess — deeper cuts on thermocouple accuracy, interrupts, logging architecture, EMI.
  • EEVblog soldering tutorial (3 parts) and Adafruit “Collin’s Lab: Soldering” — before the TS101 meets perfboard. Also search perfboard soldering techniques.
  • Concept searches: pull-up resistor open collector explained · SPI vs I2C explained · ESP32 hardware interrupt vs polling · LiPo battery safety charging storage.

Before the engine lands

  • Search Toyan FS-L200 assembly / Toyan engine build — watching a full build of this engine family is a rehearsal. JohnnyQ90 for micro nitro engine break-in and tuning by ear.
  • Search nitro engine break in procedure · nitro engine tuning rich vs lean · reading a glow plug.
  • Engineering Explained — ignition timing advance explained; then CDI vs inductive ignition; then the Speeduino and rusEFI wikis on crank trigger decoding and ignition scheduling — the working textbook for the ignition ESP32.

Background, any time

  • F1 power unit explained MGU-K — Chain Bear and the Mercedes HPP official videos; this is the architecture being miniaturized.
  • VESC tool tutorial and VESC UART control Arduino; the SolidGeek VescUart library on GitHub is the likely Phase 2 interface.
  • Star grounding explained · EMI suppression hobby electronics.

Five-hour priority order: two Random Nerd Tutorials builds with real hardware → EEVblog soldering series → one full Toyan build video → one nitro tuning video → Speeduino ignition-decoding docs. That set covers every skill Phase 1 demands.
